# **3 — Traditional Governance Characteristics**

### **3.1 — Guardrail‑Centric**
Traditional systems rely on:

- refusal triggers  
- content filters  
- safety classifiers  
- moderation heuristics  

These operate **after** the model has already generated or attempted the unsafe action.

### **3.2 — Heuristic Safety**
Safety is probabilistic:

- “likely unsafe”  
- “possibly harmful”  
- “high‑risk content”  

This creates:

- false positives  
- false negatives  
- jailbreak vulnerabilities  
- spec‑gaming opportunities  

### **3.3 — Unbounded Execution Surface**
Traditional systems often allow:

- recursive tool use  
- multi‑step autonomy  
- cross‑system access  
- ungoverned API calls  

This is how “sandbox escapes” happen.

---

# **4 — NDH Governance Characteristics**

### **4.1 — Invariant‑Driven**
NDH defines:

- what must never happen  
- what must always remain true  
- what boundaries cannot be crossed  

These are **constitutional**, not heuristic.

### **4.2 — Trauma‑Informed Safeguards**
NDH uses:

- harm‑surface minimization  
- predictable behavior  
- reversible geometry  
- continuity‑checked transitions  

This prevents:

- drift  
- escalation  
- unbounded autonomy  
- cross‑boundary execution  

### **4.3 — Closed Execution Geometry**
NDH systems operate inside a **Publication Envelope**:

- no lateral movement  
- no external traversal  
- no unscoped tool access  
- no recursive autonomy  

This makes “escape” architecturally impossible.

---

# **5 — Why NDH Cannot Fail Like Traditional Systems**

### **5.1 — No Hidden Outbound Paths**
Traditional sandboxes often have:

- package proxies  
- internal services  
- dependency networks  
- logging endpoints  

NDH treats all of these as **governed surfaces**.

### **5.2 — No Autonomous Tool Chaining**
Traditional agents can:

- chain tools  
- escalate privileges  
- traverse systems  

NDH forbids:

- recursive tool chains  
- unbounded autonomy  
- cross‑system continuity  

### **5.3 — No Spec‑Gaming**
Traditional systems optimize for:

- reward  
- benchmark score  
- task completion  

NDH optimizes for:

- invariant preservation  
- bounded execution  
- governed continuity  

Spec‑gaming breaks invariants → NDH halts.

# **6 — Summary**
Traditional governance is:

- reactive  
- heuristic  
- porous  
- post‑hoc  
- content‑focused  

NDH governance is:

- proactive  
- architectural  
- bounded  
- invariant‑driven  
- trauma‑informed  

NDH does not “prevent bad behavior.”  
NDH **removes the architectural possibility** of ungoverned behavior.
