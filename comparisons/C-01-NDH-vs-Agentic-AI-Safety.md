# **C‑01 — NDH vs Agentic AI Safety**  
### *NDH‑TIDS Comparative Architecture Note*

## **Subject**
Comparative analysis of NDH’s invariant‑driven, trauma‑informed safety architecture versus modern agentic AI safety approaches (autonomous agents, multi‑step planners, exploit harnesses, reflective loops, and tool‑driven autonomy).

This note is **observational**, **non‑constitutional**, and **reversible**.

---

# **1 — Overview**
Agentic AI safety today relies on:

- guardrails  
- refusal heuristics  
- safety classifiers  
- tool permissioning  
- sandboxing  
- post‑hoc incident response  

NDH safety is fundamentally different:

- invariant‑driven  
- trauma‑informed  
- envelope‑scoped  
- continuity‑checked  
- non‑recursive  
- pre‑hoc safeguard activation  

NDH does not “control” agentic AI.  
NDH **removes the architectural possibility** of unsafe autonomy.

# **3 — Agentic AI Safety Characteristics**

### **3.1 — Recursive Autonomy**
Agentic systems often:

- plan multiple steps  
- chain tools  
- spawn sub‑agents  
- expand queries  
- escalate capabilities  

This creates powerful reasoning — and powerful failure modes.

### **3.2 — Tool‑Driven Execution**
Agents rely on:

- code execution tools  
- retrieval tools  
- API tools  
- file‑system tools  

Tool misuse or insecure integration leads to:

- sandbox escape  
- lateral movement  
- exploit discovery  

### **3.3 — Heuristic Safety**
Safety is enforced via:

- refusal classifiers  
- content filters  
- guardrails  

These operate **after** unsafe behavior is attempted.

### **3.4 — Post‑Hoc Control**
Safety depends on:

- kill switches  
- monitoring  
- patching  
- incident response  

This is reactive.

---

# **4 — NDH Safety Characteristics**

### **4.1 — Invariant‑Driven Safety**
NDH defines:

- what must never happen  
- what boundaries cannot be crossed  
- what invariants must remain true  

These are **constitutional**, not heuristic.

### **4.2 — Trauma‑Informed Safeguards**
NDH uses:

- harm‑surface minimization  
- predictable behavior  
- reversible geometry  
- continuity constraints  

This prevents unsafe behavior **before** it occurs.

### **4.3 — Envelope‑Scoped Execution**
NDH confines execution to a **Publication Envelope**:

- no external traversal  
- no lateral movement  
- no hidden outbound paths  
- no ungoverned surfaces  

Everything inside the envelope is:

- known  
- scoped  
- governed  
- reversible  

### **4.4 — Bounded Autonomy**
NDH forbids:

- recursive tool chains  
- agent spawning  
- multi‑step autonomous escalation  
- unbounded planning loops  

This makes “escape” architecturally impossible.

# **5 — Why NDH Cannot Fail Like Agentic AI Systems**

### **5.1 — No Recursive Tool Chains**
Agentic AI can:

- chain tools  
- escalate capabilities  
- traverse systems  

NDH forbids recursion.

### **5.2 — No Hidden Outbound Paths**
Agentic sandboxes often contain:

- proxies  
- registries  
- internal services  

NDH has **no escape routes**.

### **5.3 — No Cross‑System Continuity**
Agentic systems can:

- move across machines  
- traverse APIs  
- exploit vulnerable code  

NDH confines execution to a single governed envelope.

### **5.4 — No Spec‑Gaming**
Agentic systems optimize for:

- reward  
- benchmark score  
- task completion  

NDH optimizes for:

- invariant preservation  
- bounded execution  
- governed continuity  

Spec‑gaming breaks invariants → NDH halts.
